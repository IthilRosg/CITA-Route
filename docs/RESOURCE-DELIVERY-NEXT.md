# Подтверждение загрузок и развитие обнаружения ресурсов

Статус: следующий этап после 0.6.3; изменения в исходниках, не установленный публичный выпуск.

## Выполненная часть

Экспериментальный Chromium-адаптер наблюдает HTTPS GET документов и фреймов,
изображений, media, XHR/fetch, скриптов, стилей и шрифтов. Это расширяет обнаружение
неисправных назначений через существующий контроллер, без ручного списка доменов.
Настройки opt-in и разрешения расширения сохранены.

Событие `complete` сообщает о завершении сетевого запроса с 2xx и явным
`fromCache=false`. Кэш, 304, 403, 429, другие HTTP-ошибки и неизвестное происхождение
завершения передают только освобождение ticket. `ERR_BLOCKED_BY_CLIENT`, отмены,
сертификаты и неизвестные ошибки сохраняют прежнее нейтральное поведение.
Сбой и завершение одного ticket нельзя посчитать повторно. Перенаправление создаёт
новое наблюдение назначения; URL и параметры остаются внутри браузера.

Агент проверяет поколение транспорта, ревизию опубликованного решения, текущую
сессию, Auto, применённую публикацию, ручные исключения и возраст ticket менее
90 секунд. Старый/будущий результат не становится свидетельством успеха.

В `policy-state.json` добавлены `browserDeliveries`: домен, имя приложения,
опубликованный маршрут, ревизия/поколение, числа завершений и отказов, время
последнего обновления. Максимум 256 агрегатов в памяти и 32 в снимке. Агрегат
удаляется после пяти минут без новых событий; счётчики насыщаются на 1 000 000.
При смене поколения, очистке и изменении контекста существующий Clear удаляет их.
Запись на диск использует существующий цикл статуса, не каждое сетевое событие.

Это наблюдение доставки браузером, не проверка декодирования/смысла содержимого
и не доказательство фактического выхода каждого запроса. H2/H3 может использовать
соединение, созданное при старом правиле. Поэтому поле называется `publishedRoute`:
успехи не продлевают TTL решения, не снимают карантин, не разрешают QUIC fallback
и не подменяют собственные проверки. Повторные отказы новых видов ресурсов уже
используют существующую проверку и адресный выбор пути. Автоповтор остаётся только
для ранее поддержанных конкретных картинок; документы/скрипты не воспроизводятся.

Изменения wire-протокола требуют нового агента и расширения вместе. Подключать
новое расширение к агенту публичной 0.6.3 не следует. Старый адаптер с `finish`
остаётся допустимым для нового агента.

## Проверка 23 октября

Самопроверки агента и `node tools/test-browser-extension.cjs` прошли. Проверены
все восемь browser request types, исключение кэша/HTTP-отказов, одноразовое
потребление ticket, смена поколения/ревизии, срок годности, предел снимка и
сохранение карантина после единичного успешного ресурса.

В CITA TEST W11 прошли два сквозных прогона с настоящим Chromium MV3 → Native
Messaging → pipe → контроллер. Финальный: 13:11:30–13:12:06 МСК. Усиленная
проверка требует минимум два новых завершения ПОСЛЕ восстановления: успехи
начальной здоровой фазы не могут её удовлетворить. Сценарий проверяет ошибки
QUIC, частичную передачу TCP, автоматический однократный повтор картинок,
контрольные суммы полного PNG 197 069 байт и файла 262 144 байта, декодирование
PNG и сохранение отдельного уже открытого TCP/TLS-соединения. Маршруты по
умолчанию и DNS сохранены, временный /32 удалён. Это генерируемый стенд с
локальными альтернативными путями, не проверка реального публичного DPI/VPN.

Местный отчёт: `runtime/vm-lab/w11/delivery-browser-result.json`. Автоподключение
и публичный клиент основного ПК этой проверкой не изменялись.

## Следующие отдельные этапы

1. Достоверная связь наблюдения с фактическим потоком/выходом в движке; H2/H3
   coalescing и ECH должны оставлять неоднозначность явной.
2. Базовый [граф ресурсов документа-инициатора](BROWSER-DEPENDENCIES.md) реализован
   следующим изменением исходников. Полное дерево верхнего документа/iframe,
   service worker и переходов на внешний сервер скачивания требует дальнейшей
   приёмки. Связь приоритизирует проверку, но не переносит VPN-правило на соседей.
3. Молчаливые зависания: отдельные признаки прогресса с ограничениями; не считать
   бездействующий WebSocket, долгий запрос или media-паузу отказом.
4. Постоянная история подтверждённых путей по сети/приложению/протоколу/выходу,
   затем ускорение холодного выбора до отправки пользовательского потока.
5. Публичные страницы и реальные зависимости в ВМ, Edge, разные права процессов,
   расход CPU/памяти на большой выборке, а затем приёмка выпуска.

Тест успешного сетевого завершения не доказывает доступность всего интернета.
Длительный прогон и проверка реальных публичных сайтов остаются отдельными видами
приёмки; релиз 0.6.3 автоматически этими исходниками не заменяется.
