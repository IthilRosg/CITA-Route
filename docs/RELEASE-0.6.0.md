# Приёмка 0.6.0

Android остаётся отдельным планом. Выпуск объединяет кандидат 0.5.9 с устойчивым
возвратом на предпочтительный маршрут, сокращением фоновой работы и облегчённой
доставкой. Настоящий SSH/MagicDNS через Tailscale и суточная совместная работа
остаются приёмкой пользователя на втором ПК; лабораторные проверки их не заменяют.

## Маршруты и время определения

- Первое подтверждённое решение и подтверждённый fallback не задерживаются.
- Возврат VPN → DPI/direct и DPI → direct требует двух полных калибровок,
  разнесённых минимум на 15 секунд. Каждая калибровка по-прежнему требует две
  успешные TLS-пробы. Смена кандидата, неуспешная проверка, Clear и смена эпохи
  сбрасывают незавершённое подтверждение. Достоверность не продлевается ожиданием.
- Если текущий путь сам провалил обе пробы либо его DNS недоступен, подтверждённый
  новый путь применяется сразу. Отменённая проба не считается отказом.
- При оценке возврата завершаются независимые пробы текущего пути; для первого
  назначения это дополнительное ожидание не требуется. Общий бюджет остаётся 11 с,
  очередь общая для подсказок и фонового обновления, максимум две калибровки.
- Завершение калибровки будит контроллер сразу, без дополнительного ожидания
  очередного 500-мс тика. Ручные/VPN-only правила и проверка TLS сохраняют приоритет.
- Правила публикуются с существующим подтверждением движка; установленный TCP
  не переносится на другой внешний адрес. Изменения касаются новых соединений.

## Ресурсы

- Отпечаток сети в спокойном цикле обновляется не чаще раза в 2 с. События Windows
  об адресах/доступности сбрасывают кэш. Перед применением результата и на каждом
  барьере публикации отпечаток всегда перечитывается полностью.
- policy-state.json при неизменной фазе записывается максимум раз в 2 с вместо
  каждых 500 мс. Изменение фазы, ошибка и завершение публикуются сразу. Независимый
  heartbeat прогресса не замедляется.
- Проверить счётчики операций/записей до и после на одинаковом стенде, нагрузку
  маршрутизатора и policy при смешанных TCP/UDP; короткий прогон не доказывает
  отсутствие утечки. Отдельно остаётся длительная проверка второго ПК.

## Установщик и обновления

- Обычный setup содержит framework-dependent клиент/агент. Проверяет именно
  машинные x64 Microsoft.NETCore.App 8 и Microsoft.WindowsDesktop.App 8: SDK
  в профиле пользователя, x86, один Core или другой major недостаточны.
- При отсутствии компонента предлагает загрузку официального Microsoft Desktop
  Runtime прямо в установщике с прогрессом и отменой. Перед запуском проверяет
  закреплённый SHA-512 и действительную подпись Microsoft Corporation. Отмена,
  ошибка сети/целостности/прав оставляют файлы клиента прежними.
- .NET устанавливается системно, чтобы защищённая служба работала как SYSTEM до
  входа пользователя. Существующий подходящий runtime не скачивается повторно.
  Удаление CITA Route не удаляет общий runtime других программ.
- Беззвучная установка без runtime по умолчанию останавливается до замены файлов;
  явный /INSTALLRUNTIME=1 разрешает подготовку компонента для администрирования.
  Запрос UAC и требование перезагрузки при этом не обходятся.
- Выпускаются автономный `-win-x64.zip` и компактный `-win-x64-framework.zip`.
  Старые клиенты выбирают автономный ZIP. Новый клиент с машинным runtime выбирает
  компактный; без него сохраняет автономный вариант. Поэтому переход со старой
  версии через её updater может потребовать один полный архив. Установка нового
  setup подготавливает runtime для дальнейших компактных обновлений.
- Восстановление скачанной транзакции сохраняет исходный вид архива; изменение
  наличия runtime не подменяет пакет. Исчезновение runtime блокирует установку
  компактного пакета. Хеши, источник, пути, lease и откат остаются обязательными.

## Проверки перед выпуском

1. Модели стабильности/часов/границ, прямой приоритет/TLS, очереди и поколения;
   текущие тесты agent/GUI, обновлений, старого updater, установки и отката.
2. Оба настоящих пакета: версии, manifest, хеши, запуск. Настоящий setup: выбранная
   папка, настройки/профиль, ярлыки, повторная установка и удаление на стенде.
3. В ВМ: отсутствие runtime, отказ без согласия, загрузка и установка runtime,
   повторная установка без загрузки; реальное подключение и защита службы.
4. Смешанный TCP/UDP, пауза/пропадание сети, сохранение direct при ремонте моста,
   отсутствие обхода VPN-only, ограниченные повторы и корректный Stop.
5. GitHub CI для окончательного коммита; публичный выпуск только после проверки
   пакетов. Реальные игры/голос, физический сон и суточный Tailscale — отдельно.

Не включать ключи/конфиги и локальные стендовые журналы в публичные пакеты.
Срок поддержки .NET 8 и план перехода на следующий LTS вести отдельной задачей;
облегчённая упаковка не должна скрытно менять major платформы пользователя.
