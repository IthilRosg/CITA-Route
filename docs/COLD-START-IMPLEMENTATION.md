# Холодный запуск после 0.6.3: реализация и приёмка

## Состояние

Кандидат не опубликован и целиком не установлен на основном ПК. FirstUseGate
по умолчанию выключен; новый механизм удержания потока включён только в ВМ.
На основном ПК отдельно применены доменные правила Telegram Mini Apps:
пользователь подтвердил загрузку Stickers/BotFather. См. TELEGRAM-MINIAPPS-20261023.md.
Изменения обнаружения WireSock описаны в WIRESOCK-DISCOVERY.md.

## История и ограниченный прогрев

Свежие решения проверяются по сети, профилю, стратегии, режиму, clear generation
и исходному TTL. WarmHints не продлевают TTL и не разрешают маршрут: они только
планируют новую калибровку. До 256 подсказок, срок 24 часа, без URL и cookies.
Прогрев включён отдельным сохранённым Warmup, только Auto, после публикации.
До пяти калибровок в первые 30 секунд worker, интервал не менее трёх секунд,
один из двух слотов; foreground имеет приоритет. Верхняя граница HTTP body
1920 КиБ за запуск, DNS/TLS отдельно. История сохраняется не чаще раза в минуту
при обычном использовании; Clear/Stop/network/profile не принимают старые результаты.

## Удержание первого нового TCP

Изменённое ядро 1.14.3-cita.4 вызывает gate только для default fallback после
обычных правил. Ручные/локальные/Tailscale/служебные маршруты остаются выше.
Охват: TCP/443, IPv4, известные домен и приложение, system-tun/local-test.
IP-only, IPv6, UDP и QUIC этим механизмом не покрываются. Старые потоки не мигрируют.

Канал ядро–контроллер: loopback, HMAC, nonce, PID владельца, ограниченные сообщения.
До 32 клиентов, 16 на ключ, 64 сообщения. Одно исследование на app+domain+epoch.
Два собственных GET могут дать ранний body proof до полной калибровки; максимум
64 КиБ тела на пробу, пользовательские payload не читаются и не повторяются.
Ранний proof хранится 10 с в текущих поколениях controller/bridge, до 256 ключей.
Headers не считаются доказательством доставки тела. TLS ошибки не обходятся.

Если body proof ещё нет после 1 с, новый поток может временно выбрать VPN при
свежем HTTPS текущей сессии/bridge, свежем Connected watch и отсутствии recovery,
safety hold или избегаемого VPN. Это эвристика транспорта, не доказательство
доступности данного домена. Счётчик provisionalVpn отдельный, PolicyDecision и
кэш из такого выбора не создаются. Возможны географические ограничения VPN.
При неготовом транспорте/недоступном контроллере сохраняется ограниченный fallback.
Полная калибровка до 11 с не равна ожиданию gate. Неподтверждённые Headers могут
отпустить обычный default. Удержание по метаданным не гарантирует любой ресурс URL.

В Pump устранена гонка: запрос мог поступить после timestamp в начале итерации,
получить отрицательный age и немедленно уйти в direct. Возраст теперь берётся
по свежему TickCount64, отрицательное значение не является поводом выпуска.
В статистике есть releaseReason и независимые proof/provisional counters.
Connection API опрашивается не чаще 2 Гц; gate pump не превращает его в 40 Гц.

## Оставшаяся приёмка

12-часовой сценарий Run-ColdSoak проверяет два успешных холодных прогона,
совпадение SHA агента/ядра, свежесть heartbeat и HTTPS текущего поколения,
повторяет единичный отказ один раз, учитывает паузы/смены сессии. После 12 часов
останавливает только принадлежащую тесту сессию и восстанавливает параметры.
Его фактическая фаза хранится в C:\CitaLab\cold-soak-result.json, не выводится
из времени запуска или успеха коротких тестов.

Перед публикацией остаются: длительный результат финального кандидата,
реальная совместимость старых редакций WireSock (распознавание не равно backend),
финальная сборка пакета/manifest, framework-only обновление и откат.
Android, игры/голос и настоящая TCP/QUIC миграция не подтверждены этим стендом.

Длительная проверка фактически началась 23 октября 2026 в 22:27 МСК,
плановое завершение 24 октября в 10:27 МСК. Первый sample: HTTPS Verified,
bridge generation 1, private memory фоновых процессов 188,8 МБ. Это стартовый
замер, а не результат устойчивости за 12 часов. Фаза Running подтверждена
в cold-soak-result.json; внешняя автоматика/таймер в Codex не создавались.
После двойной холодной приёмки новый GUI и discovery скрипты прошли отдельный
самотест в ВМ (exitCode 0); discovery-gui-final.json. Рабочий клиент основного
ПК целиком не обновлялся, релиз не опубликован.

Уточнение пользователя: длительные проверки приостановлены, достаточно
10 минут. Запущенный 12-часовой тест остановлен по запросу пользователя,
