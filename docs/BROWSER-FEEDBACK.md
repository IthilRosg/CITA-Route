# Браузерный адаптер CITA Route

Экспериментальный адаптер Chromium MV3. Включён в исходники и подготовку следующего
пакета, на основной ПК не установлен. Native Messaging проверен в Chrome for Testing
156.0.8078.47 на Windows 10 LTSB 14393. Код регистрации поддерживает Chrome и Edge;
отдельная приёмка актуального Chrome/Edge на Windows 11 ещё требуется. Firefox
не поддерживается этим адаптером. Наличие рабочего WireSock не заменяет эту приёмку.

## Как работает

Расширение наблюдает HTTPS GET-ресурсы Image/Media/XHR через обычный `webRequest`,
без `debugger`, перехвата заголовков, чтения тела и модификации запросов. Внутри
браузера URL нужен для выделения домена и локального сравнения хеша конкретной
картинки; URL, его параметры и этот хеш не передаются в native host. Постоянная
история посещений и содержимое ответов не сохраняются. Incognito запрещён manifest.

Цепочка: расширение → Native Messaging → агент → named pipe текущего пользователя
→ единственный поток контроллера. Нет localhost HTTP-сервера, открытого веб-страницам.
Разрешён фиксированный ID расширения; проверяются родитель Chrome/Edge, полный путь
native-процесса, PID и время запуска серверного процесса, текущая сессия и поколение.
Процесс проверяется через QUERY_LIMITED_INFORMATION, без чтения его памяти.
Pipe разрешён только фактическому SID пользователя, а его владелец проверяется
клиентом. Используется medium-метка и четыре повторно используемых экземпляра.
`CurrentUserOnly` здесь не подходит: в Windows он также различает повышение прав.
Агент даёт своему пользователю только QUERY_LIMITED_INFORMATION к собственному
процессу, сохраняя прежний DACL: это необходимо и для отдельных logon-сеансов одного
аккаунта. Доступ к памяти, завершению и изменению процесса этим не предоставляется.
Discovery публикуется после создания всех четырёх каналов. Отказ создания сразу
попадает в штатный отказ необязательного адаптера, не останавливая маршрутизацию.
Это граница от веб-страниц и других пользователей, не защита от произвольного
вредоносного кода, уже исполняющегося с полномочиями владельца установки.

Сообщения бинарные, UTF-8 с 32-битной длиной; максимум 16 КиБ/32 события. Неизвестные
поля, URL вместо домена, POST, чужой origin и неверный процесс отклоняются.
Максимум четыре pipe-клиента, 16 заданий в очереди, 256 tickets на соединение;
действуют прежние лимиты контроллера и две одновременные калибровки. Расширение
держит до 128 активных ресурсов, 256 событий и 16 ожиданий подтверждения.
Чтение неполного кадра, запись и ожидание ответа ограничены сроками. Перегрузка
или отказ адаптера не останавливают основную маршрутизацию. Фоновый опрос состояния
ремонта выполняется только при наличии ошибок, максимум 15 секунд на ресурс.

После подходящей ошибки контроллер запускает собственные пробы, а не повторяет
пользовательский запрос. Сигнал о готовности возвращается только после нового
решения и canary-подтверждения правила. Для QUIC нужна применённая совместимость;
для ошибок тела — действительно изменившийся наблюдённый путь. Ручные правила,
поколение, TLS-отказы и отдельный учёт повторных браузерных ошибок сохранены.

Автоповтор касается только уже не загрузившейся картинки, совпавшей по локальному
SHA256 полного URL. Он выполняется один раз, в исходном фрейме, если элемент ещё
прикреплён к документу, URL не изменился и не содержит query, fragment, credentials.
`srcset` и `<picture>` исключены. Файлы, формы, POST, fetch и видео автоматически
не повторяются. Существующее соединение не мигрирует: если браузер повторно
использует живой повреждённый H2-поток, новое правило само по себе его не переносит.
Для молчаливого зависания без сетевой ошибки нужен следующий этап наблюдений.

## Подключение экспериментальной сборки

Нужен агент из этой же сборки, которым запускается policy worker. Старый установленный
агент команд адаптера не содержит. По умолчанию `ExperimentalBrowserFeedback=false`,
расширение также выключено. GUI сохраняет этот параметр при записи настроек.

1. Отключить маршрут. Запустить `Register-BrowserFeedback.ps1 -Root <папка клиента>`
   под тем же пользователем, что и policy worker. При необходимости указать
   `-AgentPath <путь к новому RoutePilot.Agent.exe>`. Скрипт выбирает защищённый агент,
   затем portable-путь; регистрирует только HKCU, включает параметр для следующего
   подключения. Активную сессию он не прерывает и отказывается менять её настройку.
2. В `chrome://extensions` или `edge://extensions` включить режим разработчика
   и загрузить папку `browser-extension` как распакованное расширение.
3. Подключиться в CITA Route и включить адаптер в его браузерном popup.

Расширение пока не опубликовано в магазинах. Публичный development key закрепляет ID
распакованной версии; перед публикацией магазинный ID должен быть согласован с
`allowed_origins` и кодом агента. Это не автоматическая установка расширения.

Текущая реализация рассчитана на пользовательский policy worker. SYSTEM-сеанс
загрузки до входа Windows не расширяет права pipe на всех пользователей:
адаптер там не запускается, причина записывается в события. Основная маршрутизация
работает как прежде. Для SYSTEM потребуется отдельная приёмка делегированного
пользовательского канала. Medium-браузер против повышенного агента проверен на
текущей Windows 10 VM. Windows 11/Edge, магазинная доставка, полный MSI и обновление
защищённой службы остаются отдельными воротами перед включением для всех.

Выключение в popup прекращает native-соединение. Для удаления регистрации:
`Register-BrowserFeedback.ps1 -Root <папка клиента> -Remove`; удаляются только свои
ключи и manifest, параметр отключается для следующих подключений. Уже открытый
native host перепроверяет регистрацию перед каждой пачкой и прекращает работу,
если она удалена или изменена. Само расширение удаляется в интерфейсе браузера.

не смешиваются; ошибки ресурсов во всех случаях приходят через настоящий

JS-тестом, а полный обычный пользовательский сценарий остаётся частью приёмки

через временную задачу InteractiveToken/RunLevel=LUA. Проверяются фактические
integrity RID: агент 12288 (high), браузер и native host 8192 (medium). Задачи

### Доставка файлов обновлением

Новый `Install-Release.ps1` переносит семь файлов адаптера как один проверенный
набор. Неполный набор отклоняется до изменения установки. `Verify-ReleaseUpdate.ps1`
проверяет успешную доставку, отказ неполного набора и полный откат при заблокированном
`background.js`, вместе с прежними проверками профиля, правил и владения обновлением.

Исторический updater с прежним фиксированным allowlist не скопирует новые файлы
при первом переходе: для этой экспериментальной функции нужен полный новый пакет
или установщик. После обновления распакованного расширения его нужно перезагрузить
в браузере: уже исполняющийся MV3 worker не становится новым от замены файлов.
Магазинная доставка и полный upgrade зарегистрированного защищённого агента остаются
следующими этапами. Адаптер не включён автоматически и на основной ПК не установлен.

Причина разделения прав подтверждается [документацией PipeOptions](https://learn.microsoft.com/en-us/dotnet/api/system.io.pipes.pipeoptions?view=net-10.0)
и [исходниками .NET](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.IO.Pipes/src/System/IO/Pipes/NamedPipeServerStream.Windows.cs).
Метка задаётся через `LABEL_SECURITY_INFORMATION`, которой нужен `WRITE_OWNER`,
без привилегии изменения аудита: [права SECURITY_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information).
