# Локальные зависимости документов

Статус: экспериментальные исходники после 0.6.3; новый агент и расширение должны
использоваться вместе. Разрешения и opt-in прежние.

Расширение берёт `initiator` и `documentId` из Chrome webRequest для HTTPS GET
ресурсов. Initiator — источник запроса, а не гарантированно верхняя страница:
iframe и worker нельзя приписывать сайту по одному tabId. Навигации main_frame и
sub_frame не создают связей. Отсутствующие/opaque/private/pinned источники
оставляют ресурс без родителя, но не мешают обычному наблюдению назначения.

В native-канал передаются только домен инициатора и случайный 128-битный contextId.
Браузерный UUID, tab/frame ID, URL, query и история навигации не передаются.
Входной documentId принимается как 32 hex-символа Chromium или UUID с дефисами;
считать дефисы обязательными нельзя. Наружу в обоих случаях идёт новый случайный
contextId, не производный от браузерного токена.
Два документа одного сайта получают разные contextId. Таблица браузера содержит
максимум 128 контекстов с абсолютным временем жизни десять минут, очищается при
отключении адаптера. Перенаправление сохраняет исходного инициатора, а назначение
наблюдается отдельно. Никаких догадок о связи по общему IP или CDN нет.

Агент хранит максимум 256 рёбер document/initiator → destination/resource,
максимум 32 на контекст/инициатор/приложение. Ребро содержит число наблюдений,
принятых завершений и подходящих ошибок. Возраст без обновления — пять минут.
Привязка результата к ticket, поколению транспорта и ревизии решения сохранена.
Неподтверждённая/вытесненная связь не воскрешается поздним завершением.

При принятом отказе контроллер находит максимум четыре уже наблюдавшихся соседних
назначения того же документа, приложения и эпохи. Поднимаются только те, которые
УЖЕ стоят в очереди discovery; новые задания из графа не создаются. После двух
приоритетных заданий обслуживается обычное, если оно есть. Rate limit и предел
двух параллельных калибровок не меняются. У каждого назначения собственные пробы,
маршрут и карантин; ручные исключения и правила VPN-only не наследуются от соседей.

В policy-state.json поле browserDependencies содержит максимум 32 ребра с доменами,
типом ресурса, случайным контекстом, именем приложения и счётчиками. Граф не
сохраняется между запусками как база посещений и очищается при сбросе сессии/
поколения. Диагностический архив может содержать этот текущий ограниченный снимок.

Пары длинных доменов увеличивают сообщения: расширение делит пачки не только по
32 событиям, но и по 16 000 UTF-8 байт, ниже лимита native-канала 16 384.

Эта реализация не перечисляет все ресурсы произвольного сайта заранее и не
гарантирует наблюдение отдельного внешнего сервера скачивания: новая вкладка без
достоверного контекста остаётся самостоятельным назначением. Связи верхних
документов и вложенных фреймов потребуют отдельной браузерной приёмки. Service
worker без documentId тоже не даёт оснований выдумывать родителя.

Источник семантики: [Chrome webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest).

## Проверки

Самопроверки агента проверяют изоляцию эпох/приложений/документов, отсутствие
перехода карантина на соседей, пять минут TTL, предел 32 ребра на документ и
256 глобально, отказ URL/приватным источникам в native-протоколе. Тест очереди
подтверждает порядок: два связанных задания, обычное, следующее связанное;
приоритизация отсутствующего назначения не создаёт задания.

JS-проверки покрывают два документа одного origin, отсутствие/opaque/pinned
инициатора, компактный токен Chromium, запрет выдумывать контекст навигации,
128 контекстов и десять минут TTL, непередачу исходного токена и URL, разбиение
длинных сообщений по UTF-8 байтам.

Финальный native-прогон CITA TEST W11: 23 октября, 13:30:43–13:31:46 МСК,
`runtime/vm-lab/w11/dependency-passed.json`. После исправления формата токена
получены два ребра с девятью завершениями и четырьмя ошибками реальных ресурсов.
Все события доставлены обычным MV3/native/pipe каналом; отладчик только управлял
стендом. После восстановления отдельно подтверждены два новых завершения,
полные контрольные суммы/PNG, сохранение открытого TCP/TLS и очистка /32.
Маршруты по умолчанию и DNS сохранены, native host завершился.

Это сгенерированный HTTPS/HTTP3-стенд с ресурсами одного origin. Изоляция разных
доменов и документов проверена детерминированными тестами, но публичные CDN,
вложенные фреймы и реальные серверы скачиваний требуют следующей отдельной
приёмки. Первые неудачные отчёты сохранены: одно прерывание до проверки графа,
затем выявленная несовместимость формата documentId. Они не считаются успешными
прогонами. ВМ после финальной проверки выключена, основной клиент не заменялся.
