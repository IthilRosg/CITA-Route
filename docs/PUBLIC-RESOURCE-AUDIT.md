# Публичные ресурсы: отдельный базовый замер

Измеритель `--public-resource-audit` доступен только внутри VMware, в новой
папке `C:\CitaLab\PublicResources\<GUID>`, с закреплённым Chrome for Testing.
Разрешён фиксированный набор из шести страниц: example.com, DeepL, Wikipedia,
Microsoft, пользовательская статья Ryuugames и `https://srnky.com/OeXSnt`.
Произвольный URL параметром не принимается. Набор расширен для сравнения разных
структур ресурсов, а не для добавления специальных правил этим сайтам.
Каждая страница ограничена 50 секундами; общий бюджет — 360 секунд. Отказ одной
страницы сохраняется отдельно и не отменяет измерения остальных. Старые отчёты
с двумя страницами относятся к прежней версии измерителя.

Каждая страница открывается в отдельном временном профиле с обычной проверкой
сертификатов и разрешением реальных DNS-имён. Не используются флаги принудительного
QUIC, подмена IP, netlog, авторизация, решение CAPTCHA или нажатие ссылок.
Загрузка файлов запрещена через Browser.setDownloadBehavior до навигации.
Измеритель прокручивает страницу для обычной lazy loading и проверяет decode()
первых 32 завершённых изображений с отдельным ограничением времени.

Настоящее MV3-расширение передаёт события Native Messaging → pipe → контроллер.
Контроллер в этом запуске только наблюдает: нет PolicyPublisher, вызова Apply,
собственных сетевых проб, TUN или выбора VPN. Это **guest-default baseline**,
не приёмка маршрутизации CITA Route. Сеть хоста/NAT может влиять на внешнюю
достижимость; результат нельзя без сравнения путей приписывать провайдеру.

Сохраняются домены, агрегаты картинок (loaded/broken/pending), decode-результаты,
протокол/размер/время resource timing, нормализованные сетевые ошибки и HTTP-коды
основного домена, признаки страницы проверки, домены iframe и ограниченный граф.
Полные URL/query/страницы/заголовки/тела ответов и браузерный documentId не
сохраняются в отчёт. Профиль браузера — локальный одноразовый стендовый профиль,
не часть диагностического архива пользователя.

Завершённый сбор не равен доступности сайта: HTTP 403/проверка браузера, error page,
сломанные изображения и успешные загрузки описываются отдельно. Ошибка самого
сборщика не считается успешным измерением. Маршруты и DNS ВМ сравниваются до/после,
native-регистрация удаляется, observer и браузеры завершаются.

Первый wrapper выявил несовместимость PowerShell 5.1 с пустым именем JSON-свойства
для data/blob-изображений без hostname. Агрегаты изображений теперь передаются
массивом объектов с полем domain; это ошибка измерителя, не сетевой отказ.

Следующая приёмка: тот же набор страниц через реальные direct/DPI/VPN в отдельной
сессии нового кандидата, сравнение полноты ресурсов и результата адресного
восстановления. Вложенные фреймы, opaque initiator и внешние переходы должны
сохранять явную неопределённость, пока нет подтверждённой связи документов.

## Фактический результат 23 октября

13:40:42–13:41:27 МСК: сбор завершён, маршруты и DNS ВМ не изменены. Обе страницы
дали браузерную error page с `ERR_NAME_NOT_RESOLVED`, ни одного HTTP-ответа
исходного домена не получено. Две декодированные встроенные картинки принадлежат
странице ошибки Chromium, а не статье/сокращателю. Нулевой граф здесь не доказывает
исправность наблюдения зависимостей: основной документ сайта не загрузился.
Отчёт: `runtime/vm-lab/w11/public-resources.json`.

Адаптер подключён к настоящему native host. Замер выявил, что DNS-ошибки раньше
завершали наблюдение без подсказки контроллеру. Добавлены три отдельные подсказки:
ERR_NAME_NOT_RESOLVED, ERR_NAME_RESOLUTION_FAILED, ERR_DNS_TIMED_OUT. Они запускают
обычную независимую проверку назначения, но не пополняют карантин body/transport
и не служат доказательством блокировки. Автоповтор документов не добавлен.

После правки прошли сборка, JS-тесты и отдельный offline-прогон
`--browser-feedback-logic-test`, включая повторные DNS-ошибки без карантина.
Полные самопроверки агента прошли перед этой DNS-правкой. Новая DNS-подсказка
в настоящем браузерном канале ВМ ещё не проверена.

Уточнение после последующей проверки 23 октября: прежний внешний отказ review
больше не препятствовал чтению состояния. У Ethernet0 обнаружен APIPA
169.254.254.114, отсутствуют IPv4 default route и IPv4 DNS; контрольный example.com
также не разрешается. Отчёты: runtime/vm-lab/w11/network-baseline.json и
dns-check.json. Это неисправная базовая сеть стенда; причина отсутствия DHCP
ещё не определена. Результат не доказывает блокировку сайтов. Сеть не менялась,
после проверок ВМ штатно выключена. Актуальная последовательность приёмки:
[NEXT-ACCEPTANCE-PLAN.md](NEXT-ACCEPTANCE-PLAN.md).

шлюз/DNS 192.168.252.2; разрешаются example.com, www.ryuugames.com и srnky.com,
