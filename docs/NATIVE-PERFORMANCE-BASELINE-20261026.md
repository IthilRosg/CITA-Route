# Первый ресурсный базис нативного режима

Этап B1 выполнен на CITA TEST W11 с двумя виртуальными процессорами. Сон ПК
отменён пользователем. Основная установка и сеть хоста не менялись.

## Методика

Каждый прогон: подключение и автоматическое решение, 12 секунд простоя,
6 контрольных проб с HTTPS и UDP, 8 секунд успокоения, отключение. Всего 26
ресурсных снимков за 25–27 секунд. Это базис нативного ядра, транспорта и их
защитных помощников, отдельно от контроллера стенда. Интерфейс приложения и
реальная служба SCM в эти ресурсные цифры не включены.

CPU нормирован на два процессора ВМ. Windows Job Object учитывает CPU завершившихся
помощников; измерение только живых процессов скрывало бы эту нагрузку. Private bytes
и рабочий набор записаны по процессам; пиковый commit всего job — отдельная величина.
Генератор контрольного трафика не входит в job. Контроллер включает расходы измерителя.

Кэш ОС не контролировался: запуск свежего процесса не назван холодным стартом ПК.
Продолжительность пробы включает запуск помощника, два HTTPS-запроса и UDP-обмен;
это не время загрузки сайта. Два повтора не дают надёжной оценки P95 запуска.

## Найденное и исправленное искажение стенда

В лабораторной ветке guard каждый опрос проверял UUID ВМ через новый PowerShell/WMI.
Это давало около 20% CPU всего job, хотя постоянные ядро/транспорт занимали 0,25%.
В обычном режиме LocalSystem из защищённой папки гостевая проверка уже обходилась;
снижение лабораторной нагрузки нельзя выдавать за ускорение установленного клиента.

UUID теперь читается через [GetSystemFirmwareTable](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemfirmwaretable)
из SMBIOS Type 1 с тем же точным сравнением UUID разрешённой ВМ. Проверены порядок
байтов, границы, обрезанные записи, неподдерживаемая версия и пустой UUID. При
недоступности чтения сохранён прежний WMI fallback. Чужой корректный UUID не допускается.
Частота реальной проверки WFP и критерии подтверждения защиты не ослаблялись.

## Результаты двух повторов после исправления

| Величина | Повтор 1 | Повтор 2 |
|---|---:|---:|
| CPU всего нативного job в простое | 2,31% | 2,70% |
| CPU постоянных ядра и транспорта, подмножество предыдущей строки | 0,26% | 0,39% |
| CPU контроллера стенда с измерителем | 2,06% | 2,96% |
| Пиковый commit job | 236,3 МиБ | 236,2 МиБ |
| Private bytes постоянных/попавших в снимок нативных процессов в начале | 176,4 МиБ | 176,5 МиБ |
| То же после нагрузки и успокоения | 183,5 МиБ | 183,3 МиБ |
| Инициализация нативного сеанса | 1594 мс | 1593 мс |
| Подключение после инициализации | 1931 мс | 2812 мс |
| Ожидание первого автоматического решения после контрольной пробы | 1972 мс | 1251 мс |
| Медиана шести контрольных проб | 429 мс | 404 мс |
| Отключение | 1062 мс | 964 мс |

Это результаты данного стенда и узла. Увеличение памяти после шести запросов
не доказывает утечку или её отсутствие; нужны циклы нагрузки и выход на плато.
Рабочий набор не приравнивается к commit, а показатели ВМ — к ресурсам всего хоста.

## Квитанции и безопасность

- До исправления, с разделением CPU: `runtime/native-performance-48a4342ab4884c2fa1c2f50e642ef7f1.json`.
- После: `runtime/native-performance-449e622c62a34ca7b5d1cde98e023968.json` и
  `runtime/native-performance-6d5b450ddfd44fa58db4ea5834c96ed6.json`.
- Сводка: `runtime/native-performance-comparison.json`. В первом раннем прогоне
  раздельного счётчика постоянных процессов ещё не было; его значение — null.
- Автоматическое решение, HTTPS/UDP-контроль и независимое удаление правил прошли
  во всех ресурсных прогонах. С новым guard повторена TCP-проверка сохранения
  открытых VPN/Direct соединений, очистки разрешений и повторного допуска.
- Принятый комплект этапа A сохранён отдельно в `runtime/accepted-stage-a-20261026`.
  Новый guard этапа B намеренно отклоняется упаковщиком до обновления и проверки
  соответствующих исходников: `runtime/native-performance-packaging-gate.json`.
  Это историческая проверка отказа: позднее исходники обновлены, все три компонента
  воспроизведены без сети и комплект переупакован. Новая квитанция:
  `runtime/native-corresponding-source.zip.receipt.json`, SHA-256 исходников
  `FDB9E141E14CF185E465CEBBA33F7D7917219DB0DA0E2A364302832B8317FA37`.

## Следующая работа

1. Измерить реальную службу и GUI отдельно; снизить влияние наблюдателя, выбирая
   процессы из собственного job вместо многократного обзора всех процессов ОС.
2. Добавить контролируемые циклы 200/1000 доменов, длинную передачу, смешанный
   TCP/UDP и ресурсное плато в пределах согласованных коротких прогонов.
3. Проверить расходы повторного запуска guard при неизменной частоте подтверждения
   WFP. Кэш старого подтверждения не считать заменой действующей проверки.
4. Для первого решения проверить пробуждение калибратора по новым наблюдениям уже
   существующего мониторинга вместо обязательной секундной задержки. Сохранить
   общий бюджет, объединение проверок, границы поколений и резервный таймер.
5. Только после сравнения на одинаковом стенде устанавливать целевые бюджеты и
   публиковать заявления об ускорении. Остальные пункты B/C общего плана остаются открытыми.
