# Освобождение разрешений Direct

В нативном кандидате разрешение больше не хранится обязательно до конца сессии.
Агент снимает его только после подтверждённого барьера ядра:

1. Никакое действующее правило не направляет новые соединения через этот адрес,
   порт и протокол. Учитываются все домены и приложения с общим адресом.
2. Нет устанавливаемых соединений, контрольных HTTPS-проб и открытых сокетов.
3. Ядро под той же блокировкой запрещает новые допуски и подтверждает точную
   область, владельца, сессию, поколение и ревизию правил.
4. Агент удаляет соответствующее разрешение Windows. При неполном подтверждении
   разрешение сохраняется; повторное удаление после барьера идемпотентно.

Резервирование начинается до вызова сетевого подключения. Оно заканчивается
после закрытия сокета: EOF, истечение TTL или смена политики не считаются закрытием.
Повторное применение требует сначала разрешения Windows, затем допуска ядра.
Исторические запреты не накапливаются: отсутствующая запись означает запрет допуска.
Обе таблицы ограничены 256 областями, лимит не повышался.

Очистка выполняется после публикации политики, перед выдачей новых разрешений и
периодически раз в пять секунд. Уже подтверждённые допуски переиспользуются;
действующие правила пропускаются по ограниченному монотонному сроку, чтобы не
запускать лишние проверки. Само решение об освобождении всегда подтверждает ядро.
При 256 одновременно нужных областях новые неподтверждённые адреса остаются на VPN.

Новый протокол допуска объявляется отдельно в стартовом сообщении ядра. Агент
отказывается выполнять новую логику с ядром без этой возможности. Обновлять
компоненты нужно согласованным комплектом; публичного обновления пока нет.

## Проверки

- Go: ожидающее подключение, EOF без закрытия, общий адрес другого правила,
  повторное закрытие/удаление, повторный допуск, старое поколение/ревизия/владелец,
  32 параллельных резервирования, предел 256 и 10 000 циклов очистки.
- Эти же проверки выполнены в Windows 11 без сетевого трафика:
  `runtime/native-scope-retirement-unit.json`.
- Реальный TCP в CITA TEST W11: изменение политики сохраняет открытые VPN и Direct
  соединения, активное разрешение остаётся, после закрытия снимается, затем снова
  включается. Шесть смен неиспользуемых областей не накапливают разрешения.
  Квитанция: `runtime/native-policy-session-dd20388cb74d4a9ea06030d898321de2.json`.
- Автоматическое обучение с новым протоколом также прошло:
  `runtime/native-policy-auto-aa4c7b3e147f47068989886a3e7a48fa.json`.
- Неподтверждённые операции не снимают защиту. Тестовые правила удаляются
  независимым восстановлением; рабочая сеть основного ПК не менялась.

Это приёмка реализации и коротких TCP-сценариев. Реальный UDP/DPI, физическая
смена сетевых карт, IPv6-транспорт, полный пакет и воспроизводимость новых
бинарных файлов остаются отдельными проверками. Длительный прогон не запускался.
