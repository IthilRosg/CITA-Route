# CITA Route 0.6.1: пилотная сборка

Статус на 2026-10-22: локальный кандидат, публикации GitHub Release пока нет.
База: 0.6.0. Проверенные DNS/IPv4-изменения и измерения зафиксированы в `89348e4`;
номер версии, защита установки и приёмка поставки идут следующим коммитом.

## Состав

- Раздельные сроки готовности кандидата, выбора маршрута и подтверждения правил.
- Два DNS-провайдера на каждом пути с ограниченным резервом в контроллере и ядре.
  Валидные NXDOMAIN/NODATA сохраняются, DNS direct/VPN не смешиваются.
- Ограниченный перебор публичных IPv4 до установления TCP. После TCP ошибка
  TLS/HTTP не вызывает повторной отправки данных на другой адрес.
- Ядро `1.14.3-cita.2`, соответствующие исходники и проверка рецепта/хешей.
- Секундный TCP-бюджет остаётся выключенным по умолчанию; ручные правила,
  служебные направления и Tailscale исключены из эксперимента.
- Установщик сохраняет проверяемую копию публичных файлов до замены. При сбое
  восстанавливает прежние файлы; незавершённая установка блокирует запуск
  приложения до восстановления. Личные настройки и конфиги исключены из копии.
- Атомарная запись JSON не удлиняет полное имя временного файла: исправлен
  воспроизведённый отказ Windows PowerShell 5.1 на длинном пути распакованного ZIP.

## Дополнительная проверка обычного TUN

Самостоятельный клиент `tools/tun-probe` использует обычные Windows DNS и TCP,
проверяет TLS и явно отключает HTTP-прокси. Для трёх его соединений настоящий
движок подтвердил вход `tun/system-tun` и точный путь приложения.

Ручные VPN → direct → VPN дали соответствующие разные внешние выходы. Три уже
открытых TCP сохранили сокет и внешний выход после изменения правил, без скрытого
переподключения. После настоящего обновления 0.6.0 → 0.6.1 весь сценарий повторён
22 октября в 10:19–10:20 МСК; подтверждены три потока `tun/system-tun`, прежняя
сессия и поколение маршрутизатора.

В отдельном прогоне остановлен только принадлежащий сессии VPN-мост. Новый
VPN-запрос завершился отказом, прямой TCP сохранился. Штатный наблюдатель создал
новый мост; новый нативный VPN-запрос подтвердил серверный выход. В повторе на
установленной 0.6.1 восстановление замечено через 1593 мс.
ID сессии и процесс TUN-маршрутизатора сохранились.

Два способа вызвать отказ только прямого пути не прошли проверку достаточности:
Windows Firewall не остановил наблюдавшийся direct-запрос; временные /32-маршруты
помешали и контрольному VPN-запросу. Эти попытки не считаются доказательством
автоматического перехода при отказе direct. Причина несрабатывания firewall
требует отдельного исследования; её нельзя объявлять установленной по этому тесту.
Временные правила/маршруты этих двух попыток удалены, исходный профиль восстановлен.
Автопереход при управляемом отказе подтверждён прежними изолированными тестами
контроллера/движка; соответствующий сквозной сценарий с настоящим WireSock открыт.

## Приёмка поставки

Собраны компактный и автономный ZIP, обычный setup и setup с отдельным тестовым
AppId. Финальные пакеты прошли следующие проверки в ВМ 22 октября 10:11–10:16 МСК:

| Проверка | Результат |
|---|---|
| Оба распакованных ZIP | Хеши, отсутствие выбранного чужого профиля, самопроверки именно упакованных агента и GUI; тот же длинный путь, на котором ранее был воспроизведён отказ |
| Setup | Чистая установка, повторная установка, удаление, выбранный путь с Unicode, ярлыки; пользовательские файлы сохранены |
| Занятая установка | Активная сессия отклоняет замену; блокировка публичного файла отклоняет копирование заранее |
| Настоящее прерывание setup | Тестовый setup принудительно завершён после частичного копирования; отдельный guard восстановил все 130 прежних публичных файлов, журнал `RolledBack` |
| Следующая попытка | Повторная установка после аварийного отката проходит |
| Обновляторы | Текущий и прежний updater: блокировка файла, откат и передача управления прошли |
| Обновление основной установки ВМ | Обычный setup 0.6.0 → 0.6.1; весь manifest сверён, 6 личных файлов сохранены, защищённый агент обновлён и проверен |

Приёмка выявила отдельный дефект прежнего setup: после ошибки копирования часть
публичных файлов могла остаться заменённой. Поэтому добавлен журнал установки с
проверкой хешей и восстановлением; результат подтверждён настоящим прерыванием,
а не только имитацией файловой операции. При повреждённой резервной копии
восстановление сохраняет `RecoveryFailed` и копию для следующей попытки. Проверены
ограничения пути и владельца Windows, отмена подтверждения и повтор восстановления.
Тестовый останов копирования отсутствует в обычном setup.

Граница восстановления — публичные файлы клиента и manifest. Это не полная
транзакция всех метаданных Inno Setup/ярлыков и не доказательство переживания
отключения питания во всех файловых системах. Публикация CI ещё не запускалась;
новые проверки включены в build/release workflows.

## Короткий прогон и ресурсы

Установленная 0.6.1 прошла 121 с с четырьмя выборками: новые нативные HTTPS через
VPN и direct, правильный выход VPN, защищённый health и свежие поколения обоих
наблюдателей. Отказов и восстановлений не было; по завершении маршрут остановлен,
исходные правила и профиль возвращены автоматически.

В сумму включены GUI, два агента, ядро, мост и PowerShell-наблюдатель: пик private
memory около 354 МиБ, working set 477 МиБ; средняя суммарная доля CPU всей ВМ
2,43%. ВМ имеет 2 vCPU и 4 ГиБ RAM. Это короткий стартовый отрезок, без парного
сравнения с 0.6.0 и без учёта пиков краткоживущих процессов; он не доказывает
отсутствия длительного роста памяти. Прежняя сумма около 183 МиБ не включала GUI
и PowerShell, поэтому напрямую сравнивать эти числа нельзя.

Запущен отдельный 12-часовой прогон с интервалом 45 с, одним повтором при
отказе HTTPS, проверкой поколений, ресурсов и автоматическим возвратом исходного
профиля. Первые три выборки подтверждены к 10:30 МСК 22 октября; ожидаемое
окончание около 22:28 МСК. Его результат учитывается только после фактического
завершения. При прерывании ВМ результат неполный; автоматизация чата для теста
не включалась. Состояние хранится в госте в `C:\CitaLab\Pilot\soak-progress.json`.

Перед стабильной публикацией остаются длительный прогон кандидата, Tailscale
SSH/MagicDNS второго ПК и разбор новых сбоев. Физическая VPN-only-граница,
медленный успешный SYN, IPv6/MTU и новые транспорты не заявляются проверенными
этой поставкой. [Основной план](ROUTING-DEVELOPMENT-ROADMAP.md).

Новый [архив второго ПК на 0.6.0](DIAGNOSTICS-0.6.0-2026-10-22.md) подтверждает
12 ч 10 мин одной сессии, но содержит шесть эпизодов отказа контрольного HTTPS,
включая 7,5 мин с TCP-timeout в мосте. Причина пока не локализована; этот пилот
не заявляется исправлением ночных эпизодов без отдельного воспроизведения.
