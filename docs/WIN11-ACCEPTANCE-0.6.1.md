# Windows 11: финальная приёмка 0.6.1

Стенд: пользовательская VMware ВМ CITA TEST W11, Windows 11 Pro 25H2
26200.9711, 2 vCPU, 3324 МиБ RAM. Проверки начаты 22 октября 2026 вечером
и продолжены после полуночи 23 октября по Москве. Основная сеть хоста,
VPNUS, его VPN-профили и другие ВМ не переключались. Неудачная отдельная
попытка установки ВМ удалена по проверенному UUID. MSI исключён из приёмки.

четыре повтора и четыре дополнительных проверки, все прошли. Итого закрыто

при произвольной параллельной нагрузке этим повтором не доказана.

## Браузерный канал

Chrome for Testing 156.0.8078.47, исходный MV3-адаптер с отдельным стендовым
bootstrap opt-in. Рабочие background/images/popup не заменялись тестовыми версиями.
Маршрут через TUN ограничен собственным адресом /32, TLS проверяет закреплённый
SPKI сгенерированного стендового сертификата. CDP управляет собственной страницей
и читает состояние popup; ошибки передаются обычным webRequest/native/pipe-каналом.

Пройден обычный повышенный цикл и medium/high-цикл: браузер/native host RID 8192,
агент RID 12288. Проверены QUIC→TCP, ручной приоритет, возврат HTTP/3, полный размер
и декодирование ресурсов, два обрыва тел при здоровом корне, независимая проверка
пути и однократный повтор подходящих картинок. Исходный TCP и обычный UDP сохранены;
основные маршруты и DNS до/после равны, временный /32 удалён.

Регистрация/удаление адаптера прошли: активная сессия отклонена без частичной
записи, поддельный запуск native host отклонён; после удаления ноль своих
registry-записей и native-процессов.

В 00:15:13–00:16:44 МСК 23 октября завершён полный сценарий при открытом обычном
Chrome: замена каталога пакета, заданный отказ активации, восстановление прежних
файлов и успешная следующая замена. При обеих активациях пройдены 27 групп
самопроверок. Браузер оставался открыт; в конце ноль native-процессов и временных
задач. Использован один кандидатный бинарник: это настоящая проверка блокировок
и транзакции, без заявления о двух разных версиях защищённой службы.

В заключительном цикле через MV3/native/pipe приняты шесть ошибок, готовы четыре
результата, проверены пять соединений и 35 ресурсов; CDP не передавал ошибки.
Idle native host завершился за 40 мс при открытом браузере в этом измерении.

## Уточнения стенда и границы

- До входа пользователя InteractiveToken-задача не могла запустить обычный
  браузер. После входа проверялись фактические integrity-уровни, без изменения UAC.
- Распакованный CFT требовал чтения/исполнения его публичных файлов для Chromium
  AppContainer/LPAC. Эти права добавлены только тестовому каталогу браузера;
  песочница не отключалась. Требование описано в [документации Chromium](https://github.com/chromium/chromium/blob/main/docs/design/sandbox.md).
- Лабораторный код больше не читает MainModule у запускающегося/завершающегося
  процесса: используется тот же QUERY_LIMITED_INFORMATION, путь и время запуска.
  PID собственного Chrome публикуется атомарно после закрытия временного файла.
  Ошибка начального браузерного цикла выводится до вторичных проверок retained PID.
- Управляемый отказ вносится после готовности MV3/native-канала и настоящих GET.
  Обработка самых первых событий холодного запуска расширения этим не доказана.
- Свежая папка исходников требовала файлов Bootstrap: telegram rules и logs/data.
  Проверки из процесса, начатого до входа пользователя, не принимались за
  доказательство работы HKCU; installer lifecycle повторён после входа.
- Edge, магазинная доставка, SYSTEM-делегирование, молчаливые зависания и Firefox
  не объявляются пройденными этими тестами. Адаптер выключен по умолчанию.
- Новый реальный peer WireSock в этой чистой Windows 11 не подключался. Ранее
  подтверждённые обычный WireSock/TUN и переход 0.6.0→0.6.1 на первой ВМ остаются
  отдельными результатами, см. [протокол выпуска](RELEASE-0.6.1.md).

Локальные исходные отчёты: `runtime/vm-lab/w11/`, включая `release-final.json`,
`final-retry.json`, `install-candidate.json` и браузерные отчёты. Пароли, конфиги
VPN и ключи в репозиторий/пакет не включаются.

## Дополнительный регрессионный тест после серверной проверки

Серверная сборка выявила зависимость первого использования от окончаний строк
журнала: при CRLF первый набор не назначал калибровки. Это отдельно воспроизведено
локально до исправления: LF проходил, CRLF давал `scheduled=0`.

Парсер удаляет только завершающий CR после разделения записей по LF. Регрессионный
тест создаёт оба формата явно и сохраняет прежние требования: ровно нужные домены
и приложение, без чужого failure target и служебного трафика. После изменения все
27 групп прошли и локально, и в CITA TEST W11; повтор в ВМ завершён 23 октября в
00:30:43 МСК. Параметры отбора маршрутов, ручные правила и TLS-проверки не ослаблены.

Тест watcher/recovery дополнительно отвязан от настоящего физического адаптера
GitHub runner: состояние сети задаётся внутри fixture. Сценарий `NoNetwork`
подтверждает `WaitingForNetwork`, отсутствие запуска ремонта и сохранение бюджета
попыток. Исходные проверки Stop, чужого профиля, поколений и ограничений восстановления
сохранены. Исправленный fixture прошёл Windows PowerShell 5.1 на хосте и в Windows 11.
