# CITA Route 0.6.2: распознавание архива обновления

## Причина и исправление

После добавления браузерного адаптера архив 0.6.1 содержит корневой
`manifest.json` пакета и `browser-extension/manifest.json` расширения. GUI считал
все файлы с этим именем и отказывал в загрузке и восстановлении обновления.
Проверки установки распакованного каталога этот сценарий пропустили.

Регрессия воспроизведена до исправления тем же сообщением, что у пользователя:
«В архиве должен быть один manifest.json». Корневой manifest определяется по
структуре: в самом корне архива либо внутри единственного внешнего каталога.
Вложенные manifests остаются обычными проверяемыми файлами пакета.

## Проверки

GUI загружает плоский и обёрнутый ZIP с вложенным manifest, проверяет
восстановление, отклоняет изменение корневого и вложенного manifests,
несовпадение SHA-256 и два возможных корня пакета. Проверяется удаление каталога
отклонённой операции. Лимиты ZIP и проверки путей сохранены.

`Verify-Portable.ps1 -PackageArchive` передаёт фактический собранный архив в
самопроверку GUI через локальный тестовый параметр окружения. Обе серверные
сборки проверяют полный и framework ZIP перед публикацией. Параметр читается
только при `--self-test`, пользовательский запуск его не использует.

Опубликованный framework ZIP 0.6.1 дополнительно используется для проверки
исправленного кода в Windows 11 с установленным системным Desktop Runtime.
Локальные отчёты хранятся в `runtime/vm-lab/w11/`; секреты не публикуются.

## Переход со старого клиента

Уже установленный старый GUI содержит ошибку. Для перехода нужен EXE-установщик
0.6.2: новый ZIP не может исправить код, который отказывается его распаковывать.
Нельзя обходить ошибку удалением browser manifest из готового ZIP: это нарушает
контрольные суммы и целостность адаптера. Профили и личные правила сохраняются
штатным установщиком. Следующие ZIP-обновления проверяет исправленный GUI.

## Длительная проверка ВМ

Предрелизный прогон 0.6.1 длился 12 часов: с 22 октября 13:53 до 23 октября
01:53 МСК. Получено 915 замеров, максимальный интервал между ними 67,8 секунды.
В замерах не было устаревшей защиты policy/watch и успешного прямого ответа с
выходом VPN. При завершении тест остановил свой маршрут и восстановил профиль.

Это не чистый прогон без отказов: три неуспешных VPN-замера образуют два эпизода,
95 неуспешных прямых контрольных запросов — 44 эпизода. Зарегистрировано одно
автоматическое восстановление. Прямой контроль обращался к одному HTTPS-адресу;
без дополнительных данных эти отказы нельзя приравнивать к потере всего прямого
интернета или однозначно объяснять маршрутизацией. История не сохраняла стадию
каждой такой ошибки. Средняя загрузка измеренных процессов составила 1,403% всей
вычислительной мощности ВМ; максимум private bytes — 470 МиБ.

Бинарники этого прогона отличаются от финальных опубликованных 0.6.1 и 0.6.2.
Результат не заменяет отдельный длительный прогон финального пакета.
