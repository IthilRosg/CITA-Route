# Восстановление чужого Fake-IP через VPN — 26 октября 2026

В нативный предварительный режим добавлен путь для известного конфликта
198.18.0.0/15. Установленная программа, VPNUS, hosts, DNS и сеть основного ПК
не менялись. Релиз не публиковался, WireSock Auto остаётся основным режимом.

## Поведение

Если новая TCP-связь идёт на адрес из этого диапазона и уже содержит корректное
имя назначения, ядро передаёт имя захваченному транспорту VPN. Транспорт разрешает
его через DNS профиля внутри netstack туннеля и закрепляет допустимый IPv4 для
этого CONNECT. Посторонний системный resolver при этом повторно не вызывается;
фиксированного публичного DNS/DoH в продукт не добавлено.

Сохраняются исходные байты приложения и его TLS/SNI/проверка сертификата. Уже
открытые сокеты не перенаправляются. Блокирующая доменная политика проверяется
до восстановления адреса. Настоящий публичный IP не заменяется лишь потому,
что рядом обнаружено другое имя. При отсутствии корректного имени соединение
на Fake-IP отклоняется; угадывания по общему CDN/IP и выхода напрямую нет.

Fake-IP исключён из наблюдений Direct, допуска областей и адресов политики
одинаково в Go и C#. Восстановленный путь остаётся VPN; получение настоящего
адреса не является разрешением Direct. Собственной неограниченной DNS-истории
или кэша этот механизм не создаёт. Запрос связан с контекстом захваченного
транспорта/поколения; существующий CONNECT ограничен восемью секундами.

Из смешанного ответа DNS выбирается публичный IPv4; AAAA не мешает его выбору,
но соединение по IPv6 не открывается. Отсутствие допустимого A, некорректный
ответ или приватный/служебный IPv4 приводят к отказу. Повтор пользовательского
потока на другой адрес или другой маршрут не добавлен.

## Наблюдаемость

В ответах ядра и снимке runtime доступны nativeDnsProtocol=1, fakeIpVpnDials и
fakeIpRefused. Это накопительные счётчики текущего ядра, без имён сайтов/URL.
Управляющие ответы без DNS-метаданных не должны сбрасывать сохранённые счётчики.
Статистика не означает, что открытая страница целиком отрисовалась.

## Проверки

- Policy-тесты Go: границы диапазона, нормализация имени, запрет IP вместо имени,
  wildcard/CRLF/URL, Fake-IP без имени, неподдерживаемый UDP и сохранение реальных
  адресов. Наблюдения Fake-IP не допускаются к Direct.
- Тест транспорта: порядок A/AAAA, AAAA без A, пустой/повреждённый ответ,
  приватный IPv4 рядом с публичным, Fake-IP и IPv4-mapped IPv6.
- C# self-test и очередь до 10 000 адресатов; недопустимых политик теперь 23,
  включая обе границы диапазона Fake-IP.
- Все три native-компонента воспроизведены из архива исходников без сети;
  проверка упаковки отвергает несовпавшие и неподтверждённые роли.

## Границы и следующий допуск

Это совместимость с известным чужим Fake-IP, а не полный перехват DNS Windows.
Первичный запрос приложения к системному DNS не заменяется этим изменением.
Другие диапазоны Fake-IP не угадываются; UDP/QUIC, ECH без доступного имени и
отравленный настоящий публичный IP требуют отдельного решения. Автоматическое
переключение такого пути на Direct, кэш с TTL и split-DNS для частных зон ещё
не реализованы. Все частные зоны нельзя отправлять публичному resolver.

Далее: отдельный DNS-контур с проверяемой конфигурацией и границами доверия,
удержание/отмена запросов при смене сети и профиля, репрезентативные ресурсы
страниц и ограниченные повторные испытания. Длительного прогона и сна ПК не было.
