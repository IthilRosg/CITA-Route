# DNS: совместимость транспортов и отказ сервера — 26 октября 2026

Продолжение нативного предварительного режима после `529d006`. Ссылка Kino Atlas
исключена из последующих браузерных выборок по просьбе пользователя. Исторические
квитанции не переписываются. Хост, VPNUS, hosts, системный DNS и установленный
клиент остаются без изменений; все сетевые проверки выполняются в CITA TEST W11.

## Изменение поведения

Прежнее ограничение «только TCP/53 первого DNS профиля» снято:

- Сначала отправляется ограниченный UDP A-запрос. Усечённый ответ с совпавшим
  ID/вопросом переводится на TCP; в том числе если само тело RR физически обрезано.
- При транспортной ошибке/тайм-ауте UDP пробуется TCP того же сервера. Ожидание
  UDP занимает не более 800 мс и не более трети оставшегося бюджета этого сервера.
- При недоступности сервера, SERVFAIL или REFUSED пробуется следующий DNS из
  профиля, всего не более трёх. Оставшееся время делится между оставшимися
  серверами; общий срок разрешения остаётся три секунды, а не три секунды на попытку.
- NXDOMAIN, небезопасный адрес и некорректный ответ не обходятся поиском более
  удобного результата у другого сервера. Публичный resolver извне профиля и
  разрешение средствами Windows не добавлены. DNS работает внутри VPN-netstack.

Переотправляется только собственный DNS-вопрос. Данные приложения, HTTP-запросы,
авторизация и уже открытые TCP не повторяются на других маршрутах. UDP DNS здесь
не означает допуск произвольного UDP/QUIC для Fake-IP или автоматического Direct.

UDP-приём ограничен 512 байтами без EDNS, до четырёх ответов с неверным ID/вопросом;
TCP сохраняет предел 16 КиБ. Проверки TTL/CNAME, приватных адресов, Fake-IP,
256 записей кэша и 32 незавершённых разрешений остаются прежними.

Основание выбора транспортов: [RFC 7766](https://www.rfc-editor.org/rfc/rfc7766).

## Дополнительные исправления

Перед возвратом завершённого ответа проверяется, что контекст владельца ещё жив.
Если сведения об адресах интерфейсов недоступны, отпечаток сети целиком считается
неизвестным, даже когда шлюзы/DNS удалось прочитать. Такой кэш не используется.

Усилены квитанции VM-проверок: кроме core, guard и C#-контроллера теперь отдельно
проверяется SHA-256 фактически скопированного owner-транспорта. Ранние direct-lab
квитанции без ownerSha256 не выдаются за полную сверку всех native-ролей.

## Тесты

Тесты транспорта выполняются на net.Pipe, без открытия портов хоста и запросов
брандмауэра. Проверены UDP-only, TCP-only, TC с пустым ответом, TC с оборванной RR,
приватный ответ, NXDOMAIN, SERVFAIL/REFUSED, резервный сервер, предел трёх серверов
и отмена до обращения. Вместе с ними прошли прежние тесты кэша/поколений и Go vet.

ВМ получает только временную копию peer-конфига. Для проверки резерва в ней
первым DNS назначен недоступный TEST-NET адрес 192.0.2.53, затем исходные серверы.
Файл пользователя и DNS Windows не меняются. Проверяются 16 публичных доменов,
контроль HTTPS/UDP, удерживаемый Fake-IP TCP и работа контроля после DNS-ошибки.

Предварительные прогоны: `runtime/native-dns-fallback-0190c411dcb143b7a6b3e81a30d406bb.json`
и `runtime/native-dns-fallback-ee88298247924efb86004647d8347909.json`.
В первом 15/16 ответов с первой попытки и отдельный повтор с 403, во втором
16/16. В последующем прогоне c66b09e6c322426392678ac8a3c518ab был единичный
тайм-аут kernel.org на независимом тестовом DoH-пути. Поэтому отсутствие
сбоев каждого сайта не утверждается. При первом недоступном DNS задержка
естественно растёт на время исчерпания его части бюджета; ускорением страницы
это не называется.

Для полного DNS-отказа временный профиль содержит только TEST-NET адрес.

## Ограничения

Резервирование ограничено серверами профиля; произвольный публичный fallback
не применяется. Настоящая поломка VPN, интерфейса или всех upstream DNS не
устраняется повтором запроса. NXDOMAIN не получает отрицательный кэш; частые
ошибки всё равно ограничены общим числом одновременных запросов и сроками.
Пользовательские split-DNS зоны, полный DNS-перехват Windows, ECH без имени,
автоматический Direct для Fake-IP и QUIC остаются отдельными допусками.
Длительный тест, установка на хост и публичный релиз не запускались.
